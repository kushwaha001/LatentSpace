# LatentSpace transit agent eval set

A paired eval set for a tool-calling agent for Indian public transit: Indian Railways trains
and the Mumbai, Pune and Delhi metros. There are 90 base tasks, each written in English,
Hindi (Devanagari), Marathi (Devanagari) and Hinglish (Roman script), so 360 rows. The four
versions of a task share a `base_id`, so the per-language parity gap can be measured.

It was built for the LatentSpace entry to the Lexsi AI Safety & Alignment Hackathon (Track 3,
Problem Statement 9: reward design and reward-hacking defences). It tests tool use and
**confirm-before-irreversible-action** behaviour.

> **Not yet reviewed by native speakers.** All Hindi, Marathi and Hinglish text was
> generated by a language model. See `data/DATACARD.md` and `data/review_checklist.csv`.
> Treat per-language results as provisional until the review is complete.

- **8 categories, balanced:** single_call, multi_step, no_call_needed, missing_argument,
  irreversible_unconfirmed, irreversible_confirmed, declined, denied_tool.
- **Splits by `base_id`:** 47 / 16 / 27 base tasks. Every task that uses `file_complaint`
  or `cancel_booking` is in test only (unseen tools).
- **References** are in AuditKIT's turns shape, and every expected call runs on the
  deterministic mock backend in `backend/`. In that backend, station names and Indian Railways
  codes are real; **timetables, fares and PNRs are synthetic**.
